# FlowTask — starter-проєкт для ЛР №4

Landing page вигаданого SaaS-сервісу FlowTask. Це **навчальний starter**: код
написано так, ніби його швидко зібрали під дедлайн. Сторінка виглядає прийнятно,
але містить проблеми accessibility, технічного SEO та performance — знайти,
підтвердити й виправити їх і є завданням лабораторної роботи.

Опис завдання: `/labs/lab-4/` та `/labs/lab-4/task/` на сайті курсу.

## Склад

```text
index.html          головна сторінка — основний об'єкт аудиту
about.html          друга сторінка (потрібна для sitemap і canonical)
css/styles.css      усі стилі
js/main.js          навігація, акордеон FAQ, форма, промо-банер
img/                hero, логотип, іконки можливостей, аватари
fonts/              локальний webfont
robots.txt
.nojekyll           щоб GitHub Pages не пропускав файли з підкресленням
```

Збірки немає: це статичні файли, які віддаються як є.

## Як запустити локально

Відкривати через `file://` **не** можна — так не працюють ні `robots.txt`, ні
коректні виміри завантаження. Підніміть локальний сервер у корені проєкту:

```bash
# Node
npx serve .

# або Python
python -m http.server 8000
```

Далі — `http://localhost:8000/`.

## Як задеплоїти

Аудит виконуйте на **задеплоєній** версії, а не локально.

Вміст цієї теки можна покласти або в **окремий репозиторій**, або у теку
`lab-4/` спільного репозиторію з лабораторними. Обидва варіанти робочі —
різниця лише в налаштуваннях деплою нижче.

### GitHub Pages

1. Завантажте файли в репозиторій.
2. Settings → Pages → Source: *Deploy from a branch*, гілка `main`, тека `/`.
3. Сторінка з'явиться за адресою
   `https://<username>.github.io/<repository>/` — або
   `https://<username>.github.io/<repository>/lab-4/`, якщо проєкт лежить у
   вкладеній теці.

Якщо проєкт у вкладеній теці, скопіюйте `.nojekyll` ще й у корінь репозиторію:
GitHub Pages шукає цей файл у корені опублікованої гілки.

Зверніть увагу: проєкт віддається за шляхом `/<repository>/`, а не з кореня
origin. Для одного з файлів у цьому наборі це має значення — див. §4.6
лабораторної роботи.

### Vercel

1. [vercel.com](https://vercel.com) → Add New → Project → імпорт того самого
   репозиторію.
2. Framework Preset: **Other**. Build Command і Output Directory залишіть
   порожніми — збирати нічого не потрібно.
3. Якщо проєкт лежить у вкладеній теці — **Root Directory → `lab-4`**. Без
   цього `robots.txt` не опиниться в корені origin.
4. Deploy. Проєкт віддається з кореня origin:
   `https://<project>.vercel.app/`.

Після обох деплоїв сторінка доступна за двома різними URL. Який із них обрати
канонічним — частина завдання (§7 ТЗ).

## Обмеження

- Жодного збірника, препроцесора чи фреймворку — тільки HTML, CSS і JS.
- Верстати заново не потрібно: візуальна концепція FlowTask має залишитися
  такою ж.
- FlowTask — вигаданий продукт. Тексти, відгуки й контакти — теж.
